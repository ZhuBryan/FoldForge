# FoldForge code audit — 2026-07

Scope: hunt for latent bugs in the class of the recently-found studio crash — a
floating-point boundary overrun in `resampleProfile` where `total*k/npl` rounded
one ulp above `cum[last]` and walked an index off the array, triggered only by
real photo data. The audit swept every interpolation, resampling, binary-search,
cumulative-sum walk, and index-from-float computation across the Python package
and the studio JS, plus a degenerate-input stress battery.

## Findings

| Location | Class | Severity | Status |
|---|---|---|---|
| `examples/make_studio.py` + `studio/index.html` — `subjectHeightfield` bilinear sampler | Index-from-float overrun (sibling of the known bug) | High | Fixed |
| `foldforge/origamize/surface.py` — `origamize_heightfield` | Degenerate input crashes deep with a cryptic error | Medium | Fixed |
| `foldforge/fabricate/export.py` — `to_gltf` | Empty mesh crashes on `v.min(0)` reduction | Low | Fixed |
| `examples/make_studio.py` / `studio/index.html` — `resampleProfile` clamp | The originally-reported bug | — | Verified present and identical in both files |

## Detail

### 1. `subjectHeightfield` bilinear index overrun (High) — fixed

The bilinear sampler computes grid coordinates
`gx = bx0 + (i/(nx-1))*bw` where `bw = max(1, bx1-bx0)`, then
`x0 = Math.floor(gx)`, `x1 = min(seg.w-1, x0+1)`. `x1` was clamped but `x0` (and
`y0`) were not. When the subject's mask bounding box is a single pixel wide/high
(`bx1 == bx0`), `bw` is bumped to 1, so `gx` reaches `bx0 + 1`, one past the box.
If that box sits on the far edge (`bx0 = seg.w-1`), `x0` becomes `seg.w`, and
`seg.height[y0*seg.w + seg.w]` reads off the end of the row (or, on the last row,
off the array) — producing `NaN` heights, exactly the "index walking off the
array on real degenerate data" pattern of the original bug.

Fix: clamp the base indices too —
`x0 = min(seg.w-1, floor(gx))`, `y0 = min(seg.h-1, floor(gy))`. Applied
identically in the generator (`make_studio.py`) and the delivered
`studio/index.html`.

Proof (node harness, single-pixel bbox at the far corner): the old expression
yields a non-finite height; the clamped expression yields a finite one.

The Python resampling analogues (`design/inverse.resample_arclength`,
`io._resize`, `shapes.terrain_heightfield`, `io.heightmap_from_points`,
`sim/collision` spatial hash) were all checked and are safe: they use
`np.interp` (which clamps to the data range) or `np.clip` on every
float-derived index, so none can overrun.

### 2. `origamize_heightfield` degenerate grid (Medium) — fixed

A height field with fewer than 2 rows or 2 columns has no foldable panel. A 1x1
field crashed deep inside `CreasePattern` construction with
`"edges must be an (E, 2) array"`, and 1xN / Nx1 fields silently produced a
zero-triangle mesh. Added an up-front guard raising a clear `ValueError`
("height field must be at least 2x2 to fold") plus a non-2D shape check. No
existing caller feeds sub-2x2 grids (the vision layout helper already forces a
minimum of 2 per side), so this only converts previously-invalid input into a
clear error.

### 3. `to_gltf` on an empty mesh (Low) — fixed

`to_gltf` computes the spec-required `POSITION` min/max via `v.min(0)`, which
raises `"zero-size array to reduction"` on a mesh with no vertices. `to_stl` and
`to_obj` already handled the empty case. Added a guard raising a clear
`ValueError` ("cannot export an empty mesh to glTF"). No production path emits a
zero-vertex mesh (a zero-*triangle* mesh still carries vertices), so this only
improves the error message for invalid input.

## Stress battery coverage

A degenerate-input battery (`/tmp/stress.py`, not shipped) exercised:

- `origamize_heightfield` on grids 2..40 with constant, all-zero, gradient, and
  noise fields; non-square and single-row/column shapes (2x2, 2x10, 10x2,
  1x5, 5x1, 1x1).
- `origamize_image` on constant / zero / gradient / noise / 1px / 2px images at
  grids (2,2), (4,6), (18,24).
- `origamize_profile` on domes with 2/3/5/28 pleats, a constant profile, and a
  single-segment profile; `resample_arclength` / `angles_from_curve` on
  all-identical, single-point, and two-point curves.
- `close_relief` watertightness (every edge shared by exactly two triangles) and
  finiteness across grids 2..20, mirror and flat modes, incl. an all-zero
  (flat-rim) field.
- `to_stl` / `to_obj` / `to_gltf` on empty and single-triangle meshes.
- `heightmap_from_points` on all-identical and single points.
- CLI `fold` on a 2x2 image (folds without crashing), a missing file (clean
  `error: image file not found`), and an unsupported extension (clean
  `unsupported output` message).

After the fixes, every case either succeeds with finite output or raises the
intended clear `ValueError` — no crash produces a cryptic deep traceback and no
run yields a non-finite mesh.

## Not bugs (checked, left as-is)

- `resampleProfile` in both studio files: the clamp `if(i>=cum.length) i=cum.length-1`
  is present and identical; the two files agree on the shared math.
- Miura closed form (`diff/miura.py`): `w = sqrt(a^2 - h^2)` with `h` bounded by
  `fold_limit = a*sin(gamma) < a`, and `d = sqrt(max(b^2 - sx^2, 0))` guards the
  inner root — no negative-root `NaN` in the valid range.
- Division sites throughout use an explicit `+ 1e-9` / `+ eps` epsilon or a
  `max(..., 1e-x)` guard (image normalisation, arclength, chamfer, bar
  constraints, dihedral normals).
